# 외부 주문 CSV 업로드 및 오류 해결

| 항목 | 내용 |
| --- | --- |
| 문서 ID | OPS-ORDER-001 |
| 업무 영역 | 주문 통합 |
| 버전 | 1.0 |
| 상태 | 검토 필요 |
| 기준 기능 | FORME Operations Hub 외부 주문 통합 |
| 최종 확인일 | 2026-08-12 |

## 1. 목적

외부 OMS나 마켓에서 받은 주문을 FORME Operations Hub의 표준 CSV 형식으로 검증하고, 정상 주문만 주문 데이터베이스에 반영하는 절차를 설명합니다.

파일에 오류가 일부 포함되어 있어도 원본 파일 전체를 버리지 않습니다. 시스템은 각 행을 `정상(VALID)` 또는 `오류(INVALID)`로 구분해 저장하고, 정상 행만 배치 처리 대상으로 사용합니다.

## 2. 작업 전 확인

- `주문 통합` 메뉴에 접근할 수 있는 `OPERATOR` 또는 `ADMIN` 권한이 필요합니다.
- 화면 오른쪽 위의 `CSV 양식 받기`로 최신 양식을 내려받습니다.
- 파일은 UTF-8로 저장된 `.csv` 파일이어야 합니다.
- 파일 크기는 5MB 이하이고 데이터는 최대 5,000행이어야 합니다.
- 데이터 행이 한 행 이상 있어야 합니다.

## 3. 표준 CSV 열

열 이름과 순서를 아래와 똑같이 유지해야 합니다.

```csv
source_order_id,ordered_at,sku_code,quantity,unit_price,currency,recipient_name,postal_code,address_line1,address_line2
```

| 열 | 의미 | 입력 규칙 |
| --- | --- | --- |
| `source_order_id` | 외부 시스템의 주문번호 | 필수 |
| `ordered_at` | 주문 발생 시각 | ISO-8601 형식. 예: `2026-08-02T10:30:00+09:00` |
| `sku_code` | 상품 옵션을 구분하는 SKU | 필수이며 Operations Hub에 활성 SKU로 등록되어 있어야 함 |
| `quantity` | 주문 수량 | 1 이상의 정수 |
| `unit_price` | 상품 한 개의 가격 | 0 이상의 숫자 |
| `currency` | 통화 코드 | `KRW`, `USD`처럼 영문 대문자 3자리 |
| `recipient_name` | 수령인 이름 | 필수 |
| `postal_code` | 배송지 우편번호 | 필수 |
| `address_line1` | 기본 주소 | 필수 |
| `address_line2` | 상세 주소 | 선택 |

## 4. 업로드와 검증 절차

1. 왼쪽 메뉴에서 `주문 통합`을 선택합니다.
2. `CSV 양식 받기`를 눌러 표준 양식을 내려받습니다.
3. 양식의 열 이름과 순서를 바꾸지 않고 주문 데이터를 작성합니다.
4. 파일을 업로드 영역에 끌어 놓거나 영역을 눌러 파일을 선택합니다.
5. `주문 데이터 검증`을 누릅니다.
6. 전체·정상·오류 건수와 각 행의 오류 문구를 확인합니다.

검증이 끝나면 파일 단위 작업 ID가 생성됩니다. 원본 행, 검증 상태, 오류 사유와 업로드 담당자가 데이터베이스에 함께 기록됩니다.

## 5. 오류별 해결 방법

| 화면의 오류 문구 | 원인 | 해결 방법 |
| --- | --- | --- |
| `CSV 파일을 선택해 주세요.` | 파일을 선택하지 않았거나 빈 파일임 | 내용이 있는 CSV 파일을 다시 선택 |
| `CSV 파일은 5MB 이하여야 합니다.` | 파일 크기 초과 | 주문을 여러 파일로 나누되 파일마다 헤더 포함 |
| `.csv 형식의 파일만 업로드할 수 있습니다.` | 확장자가 CSV가 아님 | 표준 양식을 CSV 형식으로 저장 |
| `CSV 헤더가 템플릿과 다릅니다.` | 열 이름 또는 순서가 다름 | 최신 양식을 다시 받고 헤더를 그대로 유지 |
| `한 번에 최대 5,000행까지 검증할 수 있습니다.` | 데이터 행이 5,000개를 초과함 | 5,000행 이하 파일로 분할 |
| `CSV 파일을 읽지 못했습니다.` | UTF-8이 아니거나 CSV 구조가 잘못됨 | UTF-8 CSV로 다시 저장하고 따옴표·쉼표 구조 확인 |
| `주문번호가 비어 있습니다.` | `source_order_id` 누락 | 외부 주문번호 입력 |
| `SKU가 비어 있습니다.` | `sku_code` 누락 | SKU 입력 |
| `등록되지 않은 SKU입니다.` | 활성 SKU 목록에 없는 코드 | SKU 오타 확인 후, 실제 신규 SKU라면 상품·SKU 등록 절차를 먼저 수행 |
| `파일 안에 같은 주문번호와 SKU가 중복되었습니다.` | 한 파일에서 동일 주문번호와 SKU 조합이 두 번 이상 등장 | 실제 중복 행을 제거하거나 수량을 한 행으로 합산 |
| `주문일시는 ISO-8601 형식이어야 합니다.` | 주문 시각 형식 오류 | `2026-08-02T10:30:00+09:00` 형태로 수정 |
| `수량은 1 이상의 정수여야 합니다.` | 0, 음수, 소수 또는 문자 입력 | 1 이상의 정수로 수정 |
| `단가는 0 이상의 숫자여야 합니다.` | 음수 또는 문자를 입력함 | 0 이상의 숫자로 수정 |
| `통화는 KRW처럼 영문 3자리여야 합니다.` | 통화 코드 형식 오류 | `KRW`처럼 영문 3자리로 수정 |
| `수령인 이름이 비어 있습니다.` | `recipient_name` 누락 | 수령인 입력 |
| `우편번호가 비어 있습니다.` | `postal_code` 누락 | 우편번호 입력 |
| `기본 주소가 비어 있습니다.` | `address_line1` 누락 | 기본 주소 입력 |

한 행에 문제가 여러 개 있으면 오류 문구가 함께 표시됩니다. 표시된 항목을 모두 수정해야 그 행이 정상으로 바뀝니다.

## 6. 정상 주문 배치 실행

1. 검증 결과에서 정상 행 수를 확인합니다.
2. `정상 주문 배치 실행`을 누릅니다.
3. 시스템은 `VALID`이면서 아직 처리되지 않은 행만 읽습니다.
4. 주문을 100행 단위 트랜잭션으로 처리합니다.
5. 완료 후 읽기·쓰기 건수, 누적 처리 수, 남은 정상 행과 격리된 오류 행을 확인합니다.

오류 행은 주문 데이터베이스에 반영되지 않고 스테이징 영역에 남습니다. 오류 행을 수정하려면 원본 CSV를 고친 뒤 새 업로드 작업으로 다시 검증합니다.

## 7. 재실행과 중복 방지

- 이미 `PROCESSED`가 된 행은 같은 업로드 작업을 다시 실행해도 처리 대상에서 제외됩니다.
- 외부 주문번호와 주문·SKU 조합에는 데이터베이스 UNIQUE 제약이 있어 중복 저장을 한 번 더 방어합니다.
- 배치 실행마다 고유한 실행 식별자를 사용하므로 실행 이력을 따로 추적할 수 있습니다.
- 실패가 발생하면 이미 성공적으로 커밋된 청크는 보존되고, 처리되지 않은 정상 행만 다음 실행 대상이 됩니다.

즉, 버튼을 다시 눌렀다는 이유만으로 이미 처리된 주문이 새 주문으로 한 번 더 저장되지는 않습니다.

## 8. 운영자가 확인할 기록

- 업로드 작업 ID
- 파일명과 담당자
- 전체·정상·오류 행 수
- 행 번호와 오류 사유
- 배치 실행 ID와 실행 상태
- 읽기·쓰기·누적 처리·미처리 건수

장애를 전달할 때는 파일의 개인정보 전체를 복사하지 말고 작업 ID, 문제가 발생한 행 번호, 오류 문구를 우선 전달합니다.

## 9. 현재 범위 밖의 정책

아래 항목은 현재 주문 CSV 검증 코드에서 확인되지 않으므로 별도 운영 정책 결정이 필요합니다.

- 이미 출고된 외부 주문의 취소·환불 연동 방법
- 개인정보가 포함된 원본 주문 행의 보관 기간과 파기 절차
- 동일 주문이 서로 다른 파일로 들어왔을 때 운영자에게 알리는 방식
- 외부 시스템별 통화·배송지 표준화 규칙
- 5,000행을 초과하는 대량 파일의 자동 분할 또는 비동기 수신 정책

## 10. RAG 답변 시 준수사항

- 이 문서에서 확인되는 절차와 규칙만 답변합니다.
- 답변에 문서 제목과 관련 절을 근거로 표시합니다.
- `현재 범위 밖의 정책`에 해당하면 추측하지 않고 담당자 확인이 필요하다고 안내합니다.
- 주문자 이름과 주소 등 개인정보를 답변에 그대로 노출하지 않습니다.
